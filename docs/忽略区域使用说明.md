# 用户指定忽略区域

1. 选择基准 PDF 和待校验 PDF，点击「⑥ 预览并设置忽略区域」。
2. 在任一页面拖动框选矩形。区域可用于两份文件，或仅 A / 仅 B；可用于全部页、当前页或指定页，例如 `1,3-5`。页码按 PDF 的实际页序，从 1 开始，与合同印刷页码可能不同。
3. 页眉 / 页脚预设圈选页顶 10% 和页底 8%。这是便于开始操作的固定预设，不是自动识别。翻页检查两份文件是否有正文落入框内；必要时删掉预设并重新圈选。
4. 点「使用这些规则」，再开始对比。取消会放弃此次区域编辑。更换 PDF 后必须重新打开预览、检查并应用区域，避免误用旧文件的圈选。
5. 「导出规则」保存 JSON，可在以后导入。文件只保存名称、适用文件、实际页码和页面比例坐标，不保存合同正文和原文件路径。不同纸张尺寸按比例应用；重新排版后仍应人工检查。

程序只排除字符边界完全处于矩形内的文字。只碰到框边的字符保留；同一文字行的框外部分也保留。预览按页面旋转后的显示坐标，比较引擎作对应坐标转换。

报告列出区域规则、实际排除文字和忽略区域中的文字变化提示。设置区域后的通过结论仅覆盖区域外文字；被排除的条款不会受到保护。被排除区域的图像、印章和签名变化也不作比较。请核对排除清单，不要将包含金额、主体、编号或义务条款的区域随意排除。

扫描页或文字提取失败不能用框选绕过；若圈掉某份文件的全部文字，也会得到「无法完整比较」。本版暂不加入 OCR。

文字内容相同但换行、分页不同，可以在排除页眉页脚后跨页对齐。编号后空白、中文空白和折行不作为正文改动，英语词和数字边界仍保留。有明确边框的表格按实际行、列重建，横向合并单元格作为完整行比较。对于英语单词断裂、跨行合并或无边框的复杂表格、字体编码错误或异常 PDF 阅读顺序，仍可能误报或无法完整比较。报告已修复整行重复展示，并保留两侧原有内容顺序。

文字命令也支持规则：

~~~powershell
python compare.py A.pdf B.pdf --profile regular --ignore-regions 忽略区域.json
python batch_compare.py --help
~~~

不存在、无效或指定了不存在页码的规则文件会报错，不会悄悄退回无区域比较。框选交互设计参考 [red6/pdfcompare](https://github.com/red6/pdfcompare) 的矩形排除功能；本项目继续使用文字比较，没有复制其 Java 源码或引入其依赖。
